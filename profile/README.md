<h2>一、第 0 天：测试账号、记录表、基线数据先备好</h2>

<p>开始之前准备三样东西：一个只用于测试的账号、一张固定格式的记录表、一份从你当前网络直连测出的基线。基线很重要，没有它就无法判断"慢"是代理的问题还是本地网络的问题。基线包含三项：到目标域名的平均延迟、DNS 解析耗时、以及一次典型请求的完整耗时。</p>

<h2>二、第 1-2 天：登录链路要测往返，不是测一次成功</h2>

<p>登录测试的关键是"往返"：登录、退出、再登录，来回五次，记录每次耗时和是否出现验证。只测一次成功没有意义。测试时把浏览器时间、出口 IP、UA 三元组一起记下来，未来出问题能对得上。</p>

<h3>怎么判断验证是正常风控还是环境问题</h3>

<p>看验证出现的时机。换设备、换地区、清 Cookie 后首次登录出现验证，属于常见风控；同一环境同一出口连续登录仍反复验证，才更像出口信誉或环境矛盾。前者等一天再试，后者才需要换地址。</p>

<p>记录耗时可以用浏览器开发者工具的网络面板，也可以用脚本模拟一次页面加载：<code>curl -x http://user:pass@host:port -o /dev/null -s -w "%{time_namelookup} %{time_connect} %{time_starttransfer} %{time_total}\n" https://claude.ai</code>。四个数字分别对应解析、建连、首字节、总耗时，哪个异常一眼能看出来。</p>

<h2>三、第 3-5 天：订阅链路要和账号资料一起看</h2>

<h3>支付前后为什么不能换线</h3>

<p>这一阶段测的是"一致性"而不是速度。账单地址、支付方式发卡地、账号注册地区、当前出口地区，四者越接近越平顺。测试时不要频繁更换出口，支付前后保持同一条线，中途换线是最常见的失败原因。</p>

<p>记录三件事：支付页是否能正常打开、提交后是否有失败提示、失败后多久恢复。如果是测试目的，建议用最小金额或试用方案，避免产生不必要的扣费。任何支付测试都要在服务条款允许的范围内进行。</p>

<h2>四、第 2 周：接口测试看的是断流和并发，不是单次延迟</h2>

<p>接口场景和网页完全不同。流式输出要求连接保持几分钟不断，长文档处理会持续传输，并发上来后单条连接的质量会被摊薄。测试项定为四个：单请求成功率、流式断流次数、五并发下的 P95 延迟、以及连续两小时长连接是否被重置。</p>

<thead><tr><th>测试项</th><th>方法</th><th>合格阈值</th><th>不合格的含义</th></tr></thead>
<tbody>

<tr><td>流式断流</td><td>连续 20 次长输出</td><td>0 次</td><td>中间设备超时过短</td></tr>
<tr><td>五并发 P95</td><td>xargs 并发压测</td><td>低于 1.2 秒</td><td>带宽或端口受限</td></tr>

<h2>五、第 3-4 周：只做观察，别改配置</h2>

<p>最后两周什么都不要改，让它自己跑。每天固定时间看一次探活日志，记录掉线时刻和恢复时长。这段时间的价值在于捕捉上游维护、运营商调度和月底结算带来的波动，这些在短期测试里根本碰不到。</p>

<h3>30 天结束怎么下结论</h3>

<p>把四个阶段的记录并排放，先看有没有硬伤（支付失败、频繁断流），再看软指标（P95、掉线时长）。硬伤有一条就换方案，软指标按你的容忍度权衡。结论写成三行：能用/不能用、适用场景、下次复测时间。</p>

<h2>常见问答</h2>

<h3>能不能压缩到三天测完？</h3>

<p>答：可以砍掉稳定性观察，但至少保留登录往返和一次长连接测试。三天测出的结论只能回答"现在能不能用"，回答不了"下个月还能不能用"。</p>

<h3>测试账号会不会影响正式账号？</h3>

<p>答：只要环境完全隔离就不会。测试账号用独立浏览器目录、独立出口、独立支付方式，不要和正式账号共用任何一项，也不要在同一设备上交叉登录。</p>

<h3>订阅测试必须真扣款吗？</h3>

<p>答：看平台是否提供试用或沙箱。没有的话用最小金额方案，测完按平台规则取消。无论哪种方式，都要遵守服务条款，不进行规避计费的操作。</p>

<h3>接口测试要跑多少请求才够？</h3>

<p>答：单请求成功率建议至少两百次，覆盖一个晚高峰；并发测试每个级别跑五十次取分位数。样本太少时分位数没有意义。</p>

<h2>合规提示</h2>

<p>本文的测试流程用于评估网络质量，须在服务商与目标平台允许的范围内执行。压测请控制频率与总量，避免对第三方服务造成负担。</p>

<p>不得以测试为名进行绕过付费、批量注册或干扰服务正常运行的行为。订阅测试产生的费用按平台规则结算。</p>

<p>测试记录中如含账号、支付等信息，应按最小必要原则保存，测试结束后及时清理。</p>
